# 按批注调整需求

**读懂批注。** 把选中的原文和用户期望的结果配对，明确最终产物应发生什么变化。例如，「删掉」可能指一句解释，也可能指整行。当上下文无法确定、且不同解读会改变验收结果时，追问。只适用于本稿的意见留作定向返修。

**分派到负责这项决定的人。** 找到产生该结果的要求及使用它的角色。编写者和审查者共用的判据写在一处，各自在派工入口用相对链接引用。交什么写进对应角色的指令，谁接手、谁裁定写进编排。优先沿用现有文档。派工时给出输入、负责范围和可验收的交付物。

**调整并校验。** 在负责的文档里改最小一处，让执行者能从原输入做出用户期望的结果。拿原例重做，检查实际产物，并用一个本应保留的相邻案例检查有没有改过头。需要独立验证时，给新执行者规则和原始输入，留出批注答案，作答后再比对。失败就追到造成误判的那句要求再改。

**精简并交付。** 合并重复规则，删去不影响决定的说明，用同样的案例复验简版。能稳定做对的规则就停在这里。交付时说明哪些批注落到了哪里、实际验过什么、还有哪项需要用户裁定。
