# 工程判断准则

将以下依据用于当前工程任务，支持形成、检验、改进和选择方案。分析深度随问题、证据和后果调整；简单选择可以简要判断后直接推进，交付形式沿用用户请求。各部分是相互关联的判断依据，不是必须逐项完成的检查清单。

本文精编自《软件工程恒常泛用准则_v1.5》第一、二节，保留原文的推导结构与适用条件。需要详细展开论证、核对概念及规则时，可读取[第一、二节原文](references/principles-v1.5.md)的对应章节。

## 判断结构（原文 §1、§2）

工程判断以有效实现真实目标、使成本与风险可接受为价值前提。

- **结构性事实**限定能够知道和保证什么。
- **工程原则**在上述价值前提下，从结构性事实说明哪些性质具有工程价值。
- **场景模型**提供当前目标、约束、环境、证据与不确定性。
- **决策模型**据此形成、筛选、改进、比较和修订候选方案。
- **派生结果与工程模式**保存可复用的推论及有条件的经验。

同一推导结构允许不同场景产生不同结论。原则不规定技术和风格的固定优先级；经验模式的名称不能代替当前问题的论证。若一个局部、可逆、低风险决定可依据现有证据直接做出，不展开完整决策模型；只使用足以改变结论的原则。

## 结构性事实（原文 §2.1）

1. **正确与合理由真实目标和约束界定。** 功能、数据、性能、资源、安全、兼容和期限等要求决定可接受范围；风格与实现优劣在该范围内比较。
2. **工程面对变化和失效的不确定性。** 需求、输入、依赖、环境、人员及认识都可能变化，当前判断可能失去前提；并非每段代码都会修改。
3. **参与者能够同时处理的信息有限。** 工具能扩大能力，仍需要局部推理、信息隐藏和外部记忆，使一次任务所需的信息可掌握。
4. **关键知识的未来可用性取决于恢复路径。** 知识需要持久保存，或能够从持久事实可靠地重新生成、推导或证明；仅存在于当前记忆中的理由没有可靠恢复保证。
5. **前提变化要求复核依赖结论。** 潜在受影响不等于必须修改；实际修订成本取决于依赖性质、验证与迁移机制、参与者及恢复方式。
6. **结论强度不能超过信息依据。** 可重复地执行规则，不能弥补规则对真实问题的信息不足。分别判断拥有的信息支持什么结论，以及机制能多可靠地维护、检查或证明它。

## 工程原则（原文 §2.2）

这些性质在其他条件相同时具有正向价值；投入多少以及冲突时如何取舍，由场景与方案比较决定。

### 减少完成任务必须同时掌握的知识

围绕一次具体理解、验证或修改，判断参与者必须同时知道什么。行数、函数数、类数和抽象层数不能直接衡量这一负担。信息隐藏应让使用者无需掌握部分内部细节，仍能正确使用或修改系统。

### 使知识、控制权与保证责任贴合真实依赖

区分目标性质、可用信息、控制权、保证责任和验证能力：分别指需要成立的条件、实际掌握的事实与规则、改变状态或行为的能力、确保性质成立的责任，以及检查或证明性质的能力。

控制权、保证责任与验证能力可以分属不同主体，但承担保证责任需要足够信息与可行执行路径，例如控制相关变化，或在结果使用前验证并拒绝。事后发现错误仅支持检测承诺。委托执行须有明确依赖条件和保证范围。

必须共同理解、验证或变化的状态与控制流应保持足够局部；能够独立成立、验证和变化的知识适合隔离。文件与接口边界不会自行消除真实依赖。

### 保留关键知识的恢复路径

对未来正确性重要的知识，选择直接保存或可靠再生的方式。代码结构、类型、验证材料、说明、生成规则和形式化模型均可提供恢复依据。可由持久事实可靠推导的结论，无需再单独写一份文档。

### 先确认信息充分性，再比较保障能力

信息决定机制能够表达和判断什么，执行与验证能力决定在此范围内能提供多强保障。更可靠、可重复的机制有价值，其结构、维护和运行成本仍需比较。类型、测试、注释与运行检查各有表达范围，不存在固定优劣顺序。

### 减少实现附加复杂度与依赖

真实目标要求的信息、状态和规则构成问题固有复杂度；实现引入的跳转、耦合、同步、重复工作和验证负担属于实现附加复杂度。在满足同一目标与约束的方案中，附加负担需要相应收益；收益相当时优先减少这些负担。需求增加后，系统不必比原来简单。

## 场景模型（原文 §2.3）

明确真实目标、硬约束和各项收益成本的重要程度，再按问题识别以下条件。这些是现实输入，不由工程原则推导。

| 条件 | 对判断有用的信息 |
|---|---|
| 寿命 | 存续时间及未来维护投入的回报；短寿命不降低不可逆操作的正确性要求 |
| 变化暴露 | 修改频率、范围、变化方式与可预测性，外部依赖的变化 |
| 知识分布 | 谁使用和修改、是否跨团队或第三方、能否共享上下文、信任条件、再次接触的间隔 |
| 运行暴露 | 频率、规模、并发、延迟、资源和外部交互；离线不意味着运行成本低 |
| 失败代价与恢复能力 | 能否发现错误、重跑或回滚，是否不可逆、污染下游或影响外部主体 |
| 证据与不确定性 | 依据来源、估计范围、未验证假设、尾部损失，以及获取信息和撤销决定的成本 |

区分目标或优先级尚未确认与目标明确但技术证据不足。前者需要需求依据及有权决定者的判断，不能靠更多实现比较解决；可调查的环境事实通过调查获取。保留区间与方向性判断，避免把缺少依据的估计写成精确数字。

## 决策模型（原文 §2.4）

通常先明确问题，再检查可行性、改进和比较候选；不确定性与分析投入贯穿全过程。新候选需重新检验，前提改变可返回问题设定。

### 1. 明确问题与初始候选

确认目标、硬约束、场景条件和暂定假设。比较对象应服务同一目标，不能用牺牲真实需求换取表面的实现优势。

检查候选是否共享未经证实的实现前提：机制服务什么目标、约束或风险？去掉后在哪种情景下失去什么？考虑沿用现状、删除机制、减少附加承诺或重分配责任。恢复能力、风险控制和有依据的未来变化也可以构成收益，并与当前投入比较。

### 2. 检查依据、保证与可行性

明确声称的性质和保证范围，分别判断信息是否支持结论、执行机制能否兑现承诺。检查只有在结果使用前完成，并能拒绝不合格结果，才能支持后续不使用不合格结果的保证；全过程性质不能仅由最终检查保证。依赖其他组件时保留相关条件。

信息不足时，结论可能是近似、保守估计、可能性判断或未决。用能区分方案的具体情景检查后果，但个别情景通过不能证明整个范围成立。

已知违反硬约束的候选退出后续优化，其他优势不能补偿。证据不足的候选保留可行性未决，按失败代价决定补证、采用有依据的保守假设或改选更稳健方案。

### 3. 分析并改进候选

识别谁掌握信息、谁改变状态、谁承担保证、谁执行验证，哪些知识必须共同掌握、哪些结论依赖当前前提。运用工程原则改善知识组织、恢复路径和保障机制。

取舍可能来自当前组织方式。尝试重组状态、职责、抽象或验证位置，或组合方案，构造保留更多收益的候选，再检验依据、可行性和成本。即使没有明显冲突，共同前提缺乏依据也值得返回问题设定；初始候选不代表全部可能性。

### 4. 比较成本与风险

比较可行方案的重要实现、阅读、修改、验证、协作、信息同步、运行和资源成本，以及故障概率与后果。权重取决于场景；团队惯例的协调收益、一致性与切换成本也在其中。

有依据确认候选 A 相比候选 B 在所有相关维度不差、至少一项更好时，A 才构成对 B 的帕累托支配，可淘汰 B。未被支配不代表全局最优；单项优势不能证明支配。互有得失时说明重要后果、估计范围和推荐理由，无需编造总分。

### 5. 处理不确定性与分析投入

除估计均值外，考虑参数偏差下的鲁棒性、决定的可逆性、低概率高损失的尾部风险，以及进一步调查的信息价值。

调查、原型、测量与候选搜索都应围绕可能改变选择或降低重要风险的疑问，其预期收益与实施、获取信息和等待成本比较。已有依据支持行动、继续分析收益有限且决定容易调整时，推进而非继续扩建分析。停止分析不免除硬约束要求的验证，也不将未决可行性变成事实。

关键前提仍不确定，而下游投入将显著提高纠错成本时，优先检视。根据实际迁移、协调、恢复方式与失败代价确定投入；依赖数量仅是线索。

### 6. 恢复依据并修订决定

对难以重新推导且误改代价大的结论，保留与风险相匹配的前提、保证范围和落实位置，载体可以是实现、验证、说明或生成规则。

目标、约束、场景、证据或候选集发生足以影响结论的变化时，从受影响前提重新判断。结合记录与当前产物复核下游：记录可能遗漏或过期，潜在影响不等于全部重写。保留仍有效内容，修改实际受影响的实现与材料，更新失效决定和旧计划；区分建议变化与已落实变化。

## 派生结果与工程模式（原文 §2.5）

推论依赖明确前提；模式帮助定位常见结构；经验实践允许场景与反例改变选择。使用时说明当前设计的具体条件与后果。

- **代理指标的判定上限：** 两个状态若可观测信息相同、目标性质不同，仅凭这些信息无法保证准确区分；随机选择也不能保证两者均正确。补充信息、限制范围，或保留近似、保守与不确定判断。
- **代理实化：** 将字段变化、覆盖率或行数等指标直接当成目标性质。明确指标实际支持的结论。
- **抽象收益与空壳抽象：** 必要知识未减少、潜在影响范围未缩小时，不能声称获得信息隐藏或依赖隔离收益。仍可能有命名、复用等价值，应与跳转和同步成本比较。
- **局部化与依赖离域：** 拆分必须共同成立、验证或变化的知识不消除依赖。局部性以能否在较小范围重建相关关系判断，不单看文件位置；独立验证、信息隐藏等拆分收益需要具体依据。
- **自动验证：** 充分信息、相关变更后实际执行、适当检查范围与失败处理共同决定其减少人工遗漏的价值。测试支持覆盖行为，证明依赖模型与前提，机制名称不保证证据强度。
- **团队惯例：** 主要成本风险相近且规范有协调价值时，无收益的偏离通常不值得；规范自身增加重要成本时可以改变选择。
- **依赖传播：** 更多潜在下游通常意味着更多复核工作，但自动迁移与验证可降低成本，少量外部或不可逆依赖也可能昂贵。
